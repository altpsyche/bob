# Module A — Config Tuneability

**Priority:** Implement first. Modules C, D, F depend on this.

## Problem

Three hardcoded problems:

1. `macros.srv` in `models.psd1` embeds `-ngl 99 --flash-attn on` as a literal string.
   Users who want to tune GPU layers or disable flash attention must edit a raw string — fragile,
   and they learn about it only by reading the macro.

2. `macros.kv` embeds `--cache-type-k q8_0 --cache-type-v q8_0` as a literal string.
   Changing to `q4_0` (half the KV VRAM) or disabling quant requires finding this macro.

3. Port `8080` is hardcoded in `scripts/start.ps1`, `scripts/up.ps1`, and `scripts/llm.ps1`.
   Running a second stack or changing ports requires editing three files.

4. All tuning edits land in git-tracked files, so `git pull` silently clobbers user settings.

## Solution

### A1 — `defaults` block in `config/models.psd1`

Add a `defaults` hashtable at the top of the root `@{}`, before `macros`:

```powershell
# Insert after line 42 (activeProfile = '16gb') and before macros block

defaults = @{
    ngl         = 99          # GPU layers loaded on VRAM. Lower to CPU-offload if OOM (e.g. 80).
    flashAttn   = $true       # Required for KV-cache quant. Set false only for CPU-only inference.
    kvQuant     = 'q8_0'      # KV cache quantization. 'q4_0' = ~50% less KV VRAM, ~1% quality cost.
                              # '' = disabled (needed for Gemma models).
    threads     = -1          # CPU threads for BLAS/prompt processing. -1 = auto. Tune if offloading.
    batch       = 512         # Logical batch size (-b). Higher = faster prefill. Max 2048. More VRAM.
    parallel    = 1           # Parallel request slots (-np). Set >1 for shared/multi-user setups.
    port        = 8080        # llama-swap API endpoint port.
    webuiPort   = 3000        # Open WebUI port.
    maxTokens   = 512         # Default max_tokens for `bob chat`.
    webuiSecret = 'bob-dev'  # Change to a real secret before exposing WebUI on LAN.
}
```

**Remove** the hardcoded values from `macros`:

```powershell
# OLD macros block (lines 48-51):
macros = @{
    srv = '${env.LLAMA_LOCAL_ROOT}/bin/llama-server.exe --port ${PORT} -ngl 99 --flash-attn on'
    kv  = '--cache-type-k q8_0 --cache-type-v q8_0'
}

# NEW macros block — values are placeholders; gen-llama-swap.ps1 fills them from defaults:
macros = @{
    srv = ''   # Generated by gen-llama-swap.ps1 from defaults. Do not edit.
    kv  = ''   # Generated by gen-llama-swap.ps1 from defaults.kvQuant. Do not edit.
}
```

> **Note:** The `macros` block in PSD1 is now empty placeholders. The generator writes real values
> into `config/llama-swap.yaml` at launch time. The PSD1 macros are kept so the schema stays
> consistent (generator reads them for key ordering), but their values are overwritten.
>
> Alternative approach: remove `macros` from PSD1 entirely and have the generator synthesize
> them from scratch. This is cleaner but requires updating any validation that checks for macros.
> **Recommended:** Remove macros from PSD1 and synthesize fully in generator (see A3).

### A3 — `scripts/_models.ps1` — merge user overrides into `Get-ModelsConfig`

Current `Get-ModelsConfig` (lines 18-21) just calls `Import-PowerShellDataFile`.

Replace with:

```powershell
function Get-ModelsConfig {
    $base = Import-PowerShellDataFile $script:ModelsFile
    $userFile = Join-Path (Split-Path $script:ModelsFile) 'user.psd1'
    if (Test-Path $userFile) {
        $user = Import-PowerShellDataFile $userFile
        # Deep-merge: user.defaults keys shadow base.defaults
        if ($user.defaults) {
            if (-not $base.defaults) { $base.defaults = @{} }
            foreach ($k in $user.defaults.Keys) {
                $base.defaults[$k] = $user.defaults[$k]
            }
        }
    }
    $base
}
```

This means: every consumer of `Get-ModelsConfig` automatically sees merged defaults.
No other scripts need to know about `user.psd1` — the merge is transparent.

### A4 — `scripts/gen-llama-swap.ps1` — build macros from defaults

Replace the static macro-emission block with dynamic construction.

Current flow (lines 48-65): emits macros verbatim from PSD1.

New flow — add **before** the YAML emission loop:

```powershell
# Build srv macro from defaults
$d = $cfg.defaults
if (-not $d) { throw 'models.psd1 is missing the defaults block. Add it per MODULE-A docs.' }

$ngl     = $d.ngl ?? 99
$fa      = if ($d.flashAttn -ne $false) { '--flash-attn on' } else { '' }
$batch   = if ($d.batch -and $d.batch -ne 512) { "-b $($d.batch)" } else { '' }
$par     = if ($d.parallel -and $d.parallel -gt 1) { "-np $($d.parallel)" } else { '' }
$thr     = if ($d.threads -and $d.threads -gt 0) { "-t $($d.threads)" } else { '' }
$srvParts = @(
    '${env.LLAMA_LOCAL_ROOT}/bin/llama-server.exe',
    '--port ${PORT}',
    "-ngl $ngl",
    $fa, $batch, $par, $thr
) | Where-Object { $_ -ne '' }
$srvMacro = $srvParts -join ' '

# Build kv macro from defaults
$kvQuant = $d.kvQuant ?? 'q8_0'
$kvMacro = if ($kvQuant) { "--cache-type-k $kvQuant --cache-type-v $kvQuant" } else { '' }

# Inject into config for YAML emission (overrides whatever PSD1 macros said)
$cfg.macros['srv'] = $srvMacro
$cfg.macros['kv']  = $kvMacro
```

**Gemma guard** — add inside the model-processing loop (after `$m` is resolved):

```powershell
if ($m.gguf -match 'gemma' -and $m.kv -eq $true) {
    Write-Warning "[$($m.role)] Gemma model with kv=`$true — KV quant causes quality regression. Set kv=`$false or set kvQuant='' in config/user.psd1."
}
```

**Note on empty kv macro:** When `kvQuant = ''`, the kv macro is an empty string `""`.
The YAML will emit `kv: ""`. Models with `kv = $true` will then expand `${kv}` to nothing,
effectively disabling KV quant. This is correct behavior.

## Edge Cases

| Case | Behavior |
|------|----------|
| `user.psd1` missing | Silently ignored; base defaults used |
| `user.psd1` has syntax error | `Import-PowerShellDataFile` throws; user sees clear parse error |
| `user.psd1` has unknown key in defaults | Silently stored in merged config; generator ignores unknown keys |
| `kvQuant = ''` with `kv = $true` on a model | kv macro = `""`; model cmd expands `${kv}` to nothing — KV quant disabled |
| `flashAttn = $false` | `--flash-attn on` omitted from srv macro; KV quant still set if kvQuant set (warn: will fail at runtime — llama-server requires flash-attn for KV quant) |
| `batch = 512` (default) | `-b` flag omitted from srv macro (reduces noise) |
| `parallel = 1` (default) | `-np` flag omitted |
| Per-model `flags` containing `-ngl` | Appended after srv macro; overrides the global ngl |
