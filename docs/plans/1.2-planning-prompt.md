## Scope of 1.2 (two items, one theme: refresh what is already here so it keeps pace, and close the rough
edges from real use)

1. **Model refresh.** Move the `coder` role off the older Qwen2.5-Coder-14B to a current local coder from
   the Qwen3.6 generation (see the research findings below for the candidates and why 30B-A3B is no longer
   the obvious pick), and refresh the cloud peers (DeepSeek, GLM, and Moonshot Kimi for multi attempt
   agentic coding). This lands per VRAM profile: no single coder fits every tier, so each profile gets a
   right sized coder rather than one model for all.

2. **Faster, tougher voice.** Replace today's whisper.cpp STT server with faster-whisper (CTranslate2) as
   the default backend (chosen from the STT research pass below; Parakeet-TDT via ONNX is the documented
   upgrade path), and harden the voice loop against device and engine failure (no mic, engine crash mid
   turn, empty transcript, backend not reachable).

**Reliable, the offload mechanism:** MoE CPU-expert offload is confirmed as the enabler for running 30-35B MoE at Q4
on 12-16 GB cards (keep always-active layers on GPU, push routed expert FFN tensors to RAM), and our

**Refuted / not established:**

**STT backends (from the dedicated STT research pass):**
- **faster-whisper (Whisper on CTranslate2) is the pragmatic cross-platform default.** Native Python
  API, built-in Silero VAD, batching, CPU int8 plus CUDA, ~2.5 GB VRAM int8 on GPU, well-trodden Windows
  CTranslate2 wheels. Lowest integration risk and it fits the record-then-transcribe loop directly. (No
  macOS Metal, which is irrelevant until 2.0.) Primary source: SYSTRAN/faster-whisper README.
- **NVIDIA Parakeet-TDT-0.6b is the accuracy/throughput leader and the upgrade path, not the default.**
  v3 multilingual (25 EU languages) 6.32% avg WER vs Whisper large-v3 7.44% at ~0.4x the params, and it
  is now NeMo-free and cross-platform via ONNX (onnx-asr; int8 ~670 MB / ~2 GB RAM), with a
  Whisper-compatible ONNX server (achetronic/parakeet) that could drop into the current whisper-server
  HTTP contract. Caveats: its headline RTFx (~3300) is BATCHED throughput, not single-utterance latency,
  and it is weak on low-end CPUs. Sources: NVIDIA HF card, Open ASR Leaderboard (arXiv 2510.06961),
  onnx-asr.
- **Moonshine** (27M/61M) is only for the smallest edge footprint; **NVIDIA Nemotron-0.6B int4** is the
  CPU-first winner only IF hard streaming (not record-then-transcribe) ever becomes a requirement.
- **Caveat on the premise:** the "4-5x faster than whisper.cpp" claim was NOT confirmed (the 4x figure is
  faster-whisper vs reference PyTorch Whisper, not vs whisper.cpp), and all cited speed numbers are
  batched throughput. A local single-utterance A/B benchmark (whisper.cpp baseline vs faster-whisper) on
  the real 16 GB GPU and the CPU tier is required before retiring whisper.cpp.

## Decisions already made (do not re-litigate; plan within them)
- **Coder lineup is per profile and hybrid (decided).** MoE Qwen3.6-35B-A3B with `--n-cpu-moe` on the
  tight 12 and 16 GB tiers (only MoE can expert-offload), dense Qwen3.6-27B on 24 and 32 GB (no offload,
  more VRAM), and a small dense coder on 8 GB and the CPU tier. Verify the exact model card and quant at
  implementation, and tune `nCpuMoe` per profile the way `ponder` already is. Reuse the existing
  `--n-cpu-moe` path; do not invent a second offload path.
- **Clean cut, no old-coder fallback (decided).** Drop Qwen2.5-Coder-14B once the new coder lands: one
  coder per tier, fewer lock and manifest entries, less to keep verified.
- Cloud peers stay opt in and routed through LiteLLM as `*-pro` roles, using each provider's
  OpenAI-compatible endpoint (Bob is OpenAI-compatible end to end; LiteLLM bridges). Refresh DeepSeek
  (done in the hotfix; the `deepseek-v4-pro` ponder mapping is confirmed, so no peer-schema change),
  refresh GLM to 4.7, and add Kimi K2.7 Code as a new peer. Do not change the local-first default.
- **STT backend: faster-whisper (CTranslate2) is the default; Parakeet-TDT via ONNX is the upgrade path
  (decided).** The swap is backend-only: `/voice`, `bob voice`, and the transcript contract stay the
  same, and reasoning-channel isolation and persisted-turn behavior are unchanged. faster-whisper's
  built-in Silero VAD covers endpointing. Keep whisper.cpp as a fallback for the first 1.2 cut, gated on a
  local single-utterance latency benchmark, then decide whether to retire it.
- Every local model change must re-pin `versions.lock` (repo, revision, sha256) and be fetched by the
  existing provisioning path, so `bob update` moves 1.1 to 1.2 lockfile to lockfile, rebuilds only what
  changed, verifies, and rolls back on failure (that path was just fixed; reuse it). Cloud peer model
  strings are not lock-pinned.
- The 1.4 inference items (broader MoE offload, speculative decoding, ik_llama.cpp CPU backend) are NOT
  in 1.2. Use `--n-cpu-moe` only as far as the coder refresh needs it.
